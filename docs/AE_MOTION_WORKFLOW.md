# 从参考视频到 AE 运动试作

本文对应 v1.2.0 本地预览版。它把画面中的全局二维运动转换成可查看的轨迹和试作关键帧，
帮助你用自己的静态素材复现运动节奏。它不恢复参考片的原工程、分层、相机或缓动参数。
当前 JSX 已通过 Node 模拟 AE 对象的合同执行检查；本轮真实 AE bridge 不在线，尚未完成真实 AE 验收。

## 1. 先读分析证据

1. 导入参考视频，运行基础分析或完整分析。基础分析也会执行分镜、CV 运动测量和运动建议；完整分析另外使用已配置的模型。
2. 在主工作区选中镜头，或打开参考库镜头。也可设置入点/出点分析不超过 60 秒的片段，再查看其中的局部镜头。
3. 在“运动轨迹”切换水平位移、垂直位移、缩放和旋转。横轴是**源视频时间**，不是均匀排布的采样编号。
4. 在“关键帧试作方案”核对“测量建议 / AI 试作假设”、实际采样覆盖、变化范围和曲线；展开属性列表查看每个实际关键帧。长列表每页 20 条。主工作区能预览原视频时，可点击实测关键帧列表中的时间，直接查看对应的源画面。

前端的位移单位是画面宽/高百分比，缩放的 100% 表示段首原大小，旋转单位为度。
平移按画面中心计算；不同跟踪段各自以段首帧为参考，缺口不连接。
“部分跟踪”表示不能把所有段累计成整镜头运动；单点不能判断变化，低纹理不能测得零运动。
“采样连续”只说明已采样帧之间连续，采样间隔里仍可能漏掉快速运动。

首尾位置相同可能是“移出后返回”。因此应看完整曲线与峰值，而非只看“起点 → 终点”。
旧记录只有端点时会明确提示中途运动未知；重新分析才会增加实际轨迹。
跟踪质量分数不是正确率，图层运动、遮挡、透视、模糊和纹理不足都可能影响全局拟合。
quality-v4 使用真实时间间隔评估平滑性，抖动需要超过噪声的多次转向、幅度与频率依据；一次往返不自动判为抖动。
分析过程流式保留相邻采样图像，避免把长镜头全部采样图像同时留在内存中。

如果分析期间参考文件被替换，最终来源检查会拒绝新结果，保留原镜头、音频与素材路径。
导入、音频重试和保存也会检查来源。遇到“内容已改变”提示时，应重新导入对应文件，不能把旧镜头与新音频混用。
原视频已缺失时，保存仍保留原内容身份；它不会因为同一路径出现另一份文件而重标旧分析。

## 2. 理解时间与数值

例如镜头范围为源视频 12–14 秒，实际采样只覆盖 12.125–13.875 秒：

| 源视频时间 | AE 镜头局部时间 | 水平位置（画面宽度 %） |
| --- | --- | --- |
| 12.125 秒 | 0.125 秒 | 0 |
| 12.375 秒 | 0.375 秒 | 10 |
| 13.875 秒 | 1.875 秒 | 0 |

这是一次右移后返回，而不是静止。AE 局部 0 秒对应源视频镜头入点 12 秒，
不是第一个采样点 12.125 秒。MRA 保留真实采样时间，不把第一个/最后一个关键帧拉到 0 秒/2 秒。

曲线按属性独立简化：水平/垂直位置容差各为 0.1 个画面尺寸百分点，缩放为 0.2 个百分点，旋转为 0.1°。
它们约束省略采样点的线性重建误差，不代表画面跟踪误差，不能证明两次采样之间的运动。
当前曲线用线性插值；没有测得原作者的 Easy Ease、速度控制柄或贝塞尔参数。
Adobe 区分时间插值与空间插值，Position 的空间插值也会改变路径；手动复现时需同时检查。
参见 [Adobe：关键帧插值](https://helpx.adobe.com/ca/after-effects/desktop/animate-in-after-effects/animation-keyframes/keyframe-interpolation.html)。

测量位置是相对起点的偏移。若合成尺寸为 `W × H`，中心锚点下的实际 AE Position 为：

```text
X = W / 2 + position_x / 100 × W
Y = H / 2 + position_y / 100 × H
Scale = [global_scale, global_scale]
Rotation = rotation
```

这些公式要求**与源画面同尺寸、中心锚点、无父层、二维图层、起始缩放 100%、旋转 0°**。
其他图层结构应先转换坐标，不能直接复制百分比为像素。AI 试作建议若标注“像素”，也不能套用百分比公式。

## 3. 导出并运行 JSX

“导出 AE 试作脚本”出现在具有有效实测曲线的方案中。服务端会重新检查测量证据；
静止、断续跟踪、仅语义推测、历史端点或无效时间/尺寸不能导出，界面会显示具体原因。
当前支持水平/垂直位置、统一缩放和二维旋转，不生成 3D 相机、分层视差、文本动画或效果插件。

1. 点击“导出 AE 试作脚本”，记录界面返回的 `.jsx` 保存位置。导出本身不会启动或控制 AE。
2. 打开 AE，先创建或打开一个工程。
3. 选择 **File > Scripts > Run Script File…**，打开刚导出的 `.jsx`。
   此菜单方式见 [Adobe：Scripts in After Effects](https://helpx.adobe.com/ca/after-effects/desktop/automate-in-after-effects/automate-animation/scripts.html)。
4. 脚本创建名为 `MRA …` 的文件夹，以及带 `CONTENT` 和 `MOTION` 后缀的两个合成。
   `CONTENT` 中是三个静态校准标记；`MOTION` 中将整个 `CONTENT` 作为一个无父层二维图层，并写入运动关键帧。
5. 先在 `MOTION` 的工作区内预览标记，确认方向、时序和往返峰值。工作区覆盖实际采样并包含最后一个采样帧；它不是额外的测量区间。
6. 打开 `CONTENT`，把静态标记替换为你自己的同尺寸静态图片/图稿。保留外层 `MOTION` 图层的中心锚点、二维、无父层及起始变换前提。
7. 回到 `MOTION`，与参考片对应源时间段比较，再按创作需要调整关键帧和缓动。保存工程由你在 AE 中执行。

**不要把已经具有同一运动的参考视频放进 `CONTENT` 再套运动。** 这会叠加参考视频本身的运动。
导出的作用是让静态素材按测量轨迹运动；如需处理原参考视频，先明确去运动或其他处理目的。

脚本为 Position 分离 X/Y 维度，让两条独立简化曲线保持各自时间，并给各属性设置线性时间插值。
它只创建独立试作项目项，不修改当前选中层、不自动导入素材、不自动保存工程。整次运行位于一个撤销组内；
若 AE 报错，可以撤销一次移除本次尝试。

合成保留完整镜头时长，采样之外没有补造关键帧。AE 在首个关键帧之前和末个之后保持端点值，
**这种保持不属于已测得的运动证据**；合成备注保存了源范围和实际覆盖范围。

## 4. 当前限制与接口

当前导出要求宽/高分别为 4–30000 像素、视频帧率为 1–999 fps、镜头至少一帧且不超过 3 小时。
若旧版 AE 无法按 100–999 fps 创建合成，脚本会尝试按原帧率的整数分之一预览（例如 120 → 60 fps）。合成注释会标明实际预览帧率，关键帧仍沿用原始时间。
轨迹尺寸须等于视频元数据尺寸，关键帧局部时间须递增且在 `[0,duration)` 内。
极短镜头可能被正确分出，但没有足够帧对生成运动曲线；单帧分析只提供静态建议。

对变帧率视频，分析仍使用实际 PTS；AE 合成使用视频元数据的单一帧率。
脚本保留秒时间，不宣称对变帧率素材完成逐帧同步还原。全局二维近似也不能表达透视形变、独立角色运动或相机景深。

集成方可调用以下无请求体的 POST 接口，成功返回 `{path, message}`：

| 对象 | 接口 |
| --- | --- |
| 当前工作项目镜头 | `/api/v1/shots/{shot_id}/export/ae` |
| 参考库镜头 | `/api/v1/library/shots/{db_id}/export/ae` |
| 已完成的片段记录镜头 | `/api/v1/selection-analyses/{rid}/shots/{shot_id}/export/ae` |

不满足证据或元数据要求返回 409；不存在的镜头为 404；写入失败为 503。
输出位于应用输出根 `ae_exports`，每次使用独立文件名。字段详见 [JSON Schema](JSON_SCHEMA.md)。

## 5. 已有验证和未验收部分

以下数字来自本轮实际生成并解码的合成 MP4。它们针对确定的平面变换和剪辑场景，
不能换算成自然视频准确率，也没有覆盖所有编码器、分辨率、VFR 模式、遮挡或美术风格。

### 分镜基准

`spatial-affine-v4` 在 11 类场景、±50ms 匹配容差下，整片和选区各得到 **TP=6、FP=0、FN=0**。
场景包括同均色换布局、明暗硬切、静态噪声、慢/快平移、单帧闪光、曝光渐变、叠化、跨内容切换、两帧插入和切镜伴闪光。
两帧插入的入/出边界分别计数。叠化按“没有硬切事件”标注，因此该结果不验证叠化识别能力。
默认不施加最短镜头时长过滤；单帧闪光与极短插入仍可能存在歧义，需人工复核。

### 运动基准

最终 quality-v4 基准使用报告格式 `encoded-motion-trajectory-v1`，包含 10 类，每类测试整片和中间选区，共 20 个区间。
配置为 320×180、名义 24 fps、3 秒、CV 目标采样 8 fps、H.264 CRF 18。
报告快照为开发工作目录的 `work/motion-benchmark-quality-v4/report.json`，对应缓存标识 `v4-time-aware-quality-stream`；
运行环境记录为 Python 3.12.14、PyAV 19.0.2、OpenCV 4.10.0、NumPy 2.5.4。
可用构建说明中的命令重新生成独立报告，不应沿用旧版 9 类/18 区间的数量。
表中成对数字顺序均为“整片 / 选区”；RMSE 在实际时间对齐后的非参考轨迹点上计算，不插值补点。

| 场景 | 结果（整片 / 选区） | 中心距离 RMSE（px） | 缩放 RMSE（百分点） | 旋转 RMSE（°） | 跟踪时长可用率 |
| --- | --- | --- | --- | --- | --- |
| 水平平移 | 连续 / 连续 | 0.1740 / 0.0665 | 0.2079 / 0.1209 | 0.0086 / 0.0080 | 100% / 100% |
| 垂直平移 | 连续 / 连续 | 0.1168 / 0.0398 | 0.0504 / 0.0139 | 0.0079 / 0.0058 | 100% / 100% |
| 中心缩放 | 连续 / 连续 | 0.0184 / 0.0302 | 0.1209 / 0.0676 | 0.0129 / 0.0079 | 100% / 100% |
| 中心旋转 | 连续 / 连续 | 0.0610 / 0.0498 | 0.1140 / 0.0417 | 0.0186 / 0.0068 | 100% / 100% |
| 复合运动 | 连续 / 连续 | 0.2541 / 0.1174 | 0.2814 / 0.1860 | 0.0391 / 0.0102 | 100% / 100% |
| 往返运动 | 连续 / 连续 | 0.0666 / 0.0721 | 0.1149 / 0.1010 | 0.0083 / 0.0058 | 100% / 100% |
| 反复交替抖动 | 连续 / 连续 | 0.0966 / 0.0542 | 0.0422 / 0.0087 | 0.0484 / 0.0193 | 100% / 100% |
| 低纹理 | 特征不足 / 特征不足 | 无测量 | 无测量 | 无测量 | 0% / 0% |
| 遮挡缺口 | 部分跟踪 / 部分跟踪 | 0.0846 / 0.0312 | 0.1028 / 0.0377 | 0.0098 / 0.0031 | 70.42% / 53.85% |
| 非均匀 PTS | 连续 / 连续 | 0.2357 / 0.1039 | 0.3043 / 0.1438 | 0.0105 / 0.0090 | 100% / 100% |

16 个区间得到连续轨迹；遮挡的两个区间各保留两段，采样点可用率分别为 76% / 64.29%。
遮挡行的误差只覆盖留下的点，不能代表缺口精度。低纹理没有误差样本，在 JSON 中为 null，不能记成零误差。
缩放误差单位是百分点，例如比例 1.10 与 1.12 相差 2 个百分点。
报告还保留帧对可用率、缺失时间、各点误差和分析耗时；具体耗时依硬件及后续实现变化，不能作为速度承诺。

在这份合成报告中，一次往返的 `shake_score` 为 0，反复交替抖动为 1；后者虽 `stability=0`，仍保留连续测量，
`confidence` 为 0.799 / 0.800。平滑性低不等于跟踪失败。这些极端得分仅描述该固定夹具，不能据此划定自然视频的通用阈值。

### 验收边界

- 自动检查覆盖缓存替换身份、轨迹复合/分段、曲线取样时间与容差、单位换算、导出拒绝条件和前端交互。
- 音频分析/缓存命中也在返回前重新核对源内容；源变化或不可读会返回错误并丢弃本轮派生结果，旧未复核缓存由新键版本隔离。
- 整片结果采用独立候选，CV/OCR 缓存等待最终来源复核后发布；整片 OCR 仅采样镜头范围内帧。短镜头时间保留原精度，不因三位小数舍入改变边界。
- Node 使用模拟 AE 对象执行生成的 JSX，核对合成、关键帧、单位转换和线性插值调用；这不是 Adobe ExtendScript 引擎或实际 AE 图像/运动验收。
- 本轮真实 AE bridge 不在线，尚未验证真实 AE 中的渲染、播放时序与不同 AE 版本兼容性。
- 本轮真实 VLM、OCR 模型和重新打包的安装器未验收；合成视频、模型替身和源码构建结果不覆盖这些部分。

复现步骤、依赖与人工验收入口见 [构建与验证](V1_0_BUILD_GUIDE.md)。在实际 AE 完成验证前，JSX 应按试作功能使用。
