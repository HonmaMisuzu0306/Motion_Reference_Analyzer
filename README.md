# Motion Reference Analyzer

面向静止画 MAD / Galgame OP / PV 创作者的镜头参考分析与 AE 拆解工具。

目标：将参考视频自动拆解为 **镜头时间轴、画面结构、运动信息、文字信息、效果推测与 AE 制作建议**，并为后续与 **LocalFX** 联动预留结构化接口。

## v1.7.0 双点跟踪与逐点复核

在同一刚性图案上选择两个标记，可将其位置、转角和等比缩放导出为 AE 空对象。工作区支持按真实时间复核各采样点，以及图案移动最远和最快的区间。[跟踪与 AE 试作步骤](docs/RELEASE_v1.7.0.md)

## v1.6.0 框选图案跟踪

在镜头详情中框住一个图案，可以查看它在画面中的移动路径，并将已确认的位置导出为 After Effects 二维空对象。适合给移动图标、铭牌或角色身上的清晰标记添加跟随标注。[试作步骤](docs/RELEASE_v1.6.0.md)

## v1.5.1 原片回查

在资料库中打开一个有实测曲线的镜头，选中 AE 关键帧后，可以直接跳回原片并暂停在对应时间。切换素材或替换原文件后，播放器会校验该镜头记录的来源。[更新说明](docs/RELEASE_v1.5.1.md)

## v1.5.0 运动试作预览

可在导出前查看 AE 校准标记在各个关键帧的位置，长镜头中的弱运动也会经过跨帧复核。[使用说明](docs/RELEASE_v1.5.0.md)

## v1.4.0 全局运动证据

对字幕条、局部图层和多平面镜头分开检查跟踪证据，支持非方形像素素材的显示画幅。[使用步骤与验证范围](docs/RELEASE_v1.4.0.md)

## v1.3.1 竖屏与镜像素材

导入会按容器中记录的旋转和镜像读取画面。代表帧、文字位置、运动测量及 AE 合成均使用显示方向。[更新说明与旧工程用法](docs/RELEASE_v1.3.1.md)

## v1.3.0 本地预览版

可为实测镜头估算素材四边留白，直接导出已设好画布和锚点的 AE 模板。[使用步骤与示例](docs/RELEASE_v1.3.0.md)

## v1.2.0 本地预览版

在主工作区选中短镜头，展开实测关键帧列表，点击时间即可在原片中核对转折。短镜头跟踪不完整时可加密采样重试，重复字幕按各自出现区间给出 AE 建议。本地安装包名为 `MRA-1.2.0-x64-setup.exe`。已有记录需重新分析才能获得新测量。

[本版使用步骤、测速与验证范围](docs/RELEASE_v1.2.0.md) · [在 After Effects 中试作](docs/AE_MOTION_WORKFLOW.md)

## v1.1.1 旋转分镜修复

修复 v1.1.0 将连续旋转误判为大量切镜的问题；建议改用 v1.1.1，并重新分析受影响的视频。详见 [修复说明](docs/RELEASE_v1.1.1.md)。

## v1.1.0 源码预览版

增强视频分镜、真实时间运动轨迹、关键帧建议与 AE JSX 导出，并修复来源校验和缓存一致性。详见 [v1.1.0 更新说明](docs/RELEASE_v1.1.0.md)。本地交付包含源码预览包及 `MRA-1.1.0-x64-setup.exe`；尚未发布 GitHub Release。

## 快速开始

### Python 核心

```bash
cd core
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
uvicorn app.main:app --reload --port 8000
```

或直接从项目根目录启动：

```bash
python scripts/start_server.py
```

### 前端

```bash
cd apps/desktop
npm install
npm run tauri dev
```

`scripts/start_server.py` 优先使用 `core/.venv` 的 Python。M6 音频依赖 librosa 随核心安装；前端本次已通过 TypeScript 与 Vite 构建验证。

### M6 音频节奏

导入含音轨的视频并点击“分析视频”，查看音频节奏面板中的 BPM、Beat/onset、切镜同步率及时间轴。点击镜头可定位播放并查看有符号的偏差；“重新分析音频”只重算音频，不调用视觉或 OCR 模型。

默认同步容差为 ±80ms。无音轨、静音、节拍不足会明确显示不可判断。JSON、Markdown、AE Recipe 与 Library 都保留节奏结果。V1.0 使用 schema6；时间原点无法确认的非零时间戳旧镜头需重新分析视频。

可复现的合成 MP4 验收：`core/.venv/Scripts/python.exe scripts/accept_audio.py`（Windows）。该脚本真实运行音频算法，Vision/OCR 使用 Mock，结果只写 `output/m6_acceptance` 的独立库。真实模型及局部分析验收入口见[构建说明](docs/V1_0_BUILD_GUIDE.md)。

## 开发版改进（未发布）

开发分支增加了从实际视频采样到 AE 试作的完整路径：

- **运动轨迹**：按真实源视频时间组合变换矩阵，显示画面中心的水平/垂直位移、缩放和旋转。往返运动保留中途峰值；跟踪中断后分段显示，不跨缺口累加。
- **关键帧建议**：区分测量依据与 AI 试作假设，显示实际覆盖时间、每个属性的曲线和可展开的关键帧表。可靠静止测量不会被语义推近判断覆盖。
- **AE JSX 导出**：主工作区、参考库和已完成的片段分析均可导出合格的连续实测曲线；在 AE 中运行后，新建独立的 `MOTION` / `CONTENT` 合成，供替换静态素材并校对运动。
- **分镜与缓存**：`spatial-affine-v4` 结合空间颜色、连续平移/旋转/缩放及单帧闪光证据，默认保留短镜头；CV 缓存以源内容 SHA256、精确时间范围、采样配置和算法版本区分，避免同名替换素材命中旧结果。

CV 使用实际时间间隔描述平滑性和反复抖动，并流式处理采样图像。音频分析在请求开始及返回/写缓存前复核源内容；
分析期间替换素材或读取失败会明确报错，不把本轮结果写进旧身份缓存。旧音频缓存由新版本键隔离。
整片结果先在独立候选中生成，源身份最终复核后才替换工作项目并发布 CV/OCR 缓存；复核失败会保留原镜头、音频和素材路径。
导入、音频重试和手动保存也核对项目的来源，避免把替换文件的结果归到旧项目。

开始使用请阅读 [AE 运动分析与试作流程](docs/AE_MOTION_WORKFLOW.md)；字段和接口见
[开发版数据说明](docs/JSON_SCHEMA.md)，复现命令见 [构建与验证](docs/V1_0_BUILD_GUIDE.md)。

当前合成分镜基准为 **11 类场景，整片/选区各 TP=6、FP=0、FN=0**（匹配容差 ±50ms）；
最终 CV quality-v4 合成运动基准为 **10 类、20 个区间**，其中 16 个连续测量、2 个遮挡区间保留分段、2 个低纹理区间明确不可测。
这些结果不代表自然视频准确率，也不验证叠化召回率。跟踪质量分数是工程判据，不是概率。

这些改进尚未打包到上方 V1.0.0 安装器。JSX 已做 Node 模拟 AE 对象的合同执行检查，
本轮真实 AE bridge 不在线，尚未完成真实 AE 验收；真实 VLM、OCR 和安装器也未完成本轮验收。
分镜仍是启发式硬切检测，曲线只是采样范围内的复现起点，不能还原源 AE 工程或原始缓动。

## 核心原则

1. 先做可靠的数据流水线。
2. 传统算法解决能量化的问题。
3. VLM 解决语义问题。
4. 不让 AI 把“推测”写成“事实”。
5. 所有 AI 输出必须结构化。
6. 所有分析步骤必须可重试。
7. 所有昂贵步骤必须缓存。
8. MVP 不与 LocalFX 强耦合。
